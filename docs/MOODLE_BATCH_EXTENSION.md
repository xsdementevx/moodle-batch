# Рабочее расширение Moodle Batch

## Запуск

Из каталога проекта:

```powershell
npm run batch:serve
```

Сервис подготовит локальную папку `.playwright-mcp/batch/extension`.
Откройте управление расширениями Яндекса, включите режим разработчика и загрузите
эту папку как распакованное расширение. Папка `batch-extension` — исходники;
загружать надо подготовленную папку, содержащую локальную настройку подключения.
Она исключена из Git, как и cookies, токены и ответы.

Нужны cookies Moodle в `.playwright-mcp/reference-auth/cookies.json`, вход в ChatGPT
в обычном Яндексе и установленное Microsoft Playwright Extension.
Сервис использует существующие настройки Playwright Extension и ключ Jev.
По умолчанию работает порт 49805; `--port`, `--auth`, `--root`, `--origin`,
`--gpt-profile` и `--gpt-browser` позволяют задать другие локальные параметры.
Текущий интерфейс рассчитан на `https://sdo.sibupk.su`.

## Использование

На странице теста или оценок появляется кнопка Moodle Batch. Ещё можно открыть
панель значком расширения. Выберите отдельные тесты либо включите фильтр
«Только ниже 90%» и нажмите «Выбрать показанные».

«Решить и отправить выбранные» создаёт пакетный запуск. Для каждого теста сервис:

1. Импортирует доступные результаты предыдущих попыток.
2. Продолжает активную попытку либо создаёт новую обычным запросом Moodle.
3. Получает все страницы вопросов и материалы, включая PDF и Word.
4. Использует подтверждённые ответы, затем Jev и GPT Web с веб-поиском.
5. Отправляет один полный запрос с нативными полями Moodle.
6. Получает итоговый обзор, сохраняет подтверждения и ошибочные комбинации.

Можно ограничить запуск одной, двумя или тремя попытками на тест. Повторы
прекращаются при 100%, отсутствии итоговой процентной оценки, ошибке или остановке.
100% — цель, подтверждаемая Moodle; модель не гарантирует её для каждого набора вопросов.
Панель показывает фактическую оценку и ссылку на результат.

«Остановить» запрещает следующий этап и новую попытку после окончания текущего
запроса. Уже отправленный тест дочитывается для сохранения обратной связи.
Закрытие панели не отменяет запуск: он выполняется в Node.
При потере ответа на запрос запуска панель сохраняет его идентификатор и выбранные
тесты, показывает «Проверить сохранённый запуск» и блокирует изменение этого набора
до проверки. После переоткрытия она находит принятый запрос в истории без повторного
запуска. Явный отказ сервиса очищает отклонённый запрос и разрешает новый выбор.

Перезапуск сервиса помечает незавершённую работу как прерванную и не начинает попытки автоматически.
Неопределённые исходы POST и модельных запросов сохраняют существующие защитные
журналы и требуют проверки перед повтором.

Сводка появляется из кеша расширения сразу; актуальные данные загружаются в фоне.
При открытии панели анализ обновляется, если кеш старше пяти минут. Обычный опрос
состояния не запускает новый полный обход. После отправки теста его оценка читается
из журнала оценок Moodle и обновляется в сводке сразу; это учитывает отличия между
оценкой текущей попытки и итоговой оценкой теста.
Используется тот же SQLite и кеш контекста, что у пакетного запуска. Скрипты
расширения не заполняют формы Moodle. Playwright работает в локальном сервисе;
веб-провайдер использует установленное Playwright Extension в личном браузере.
Служебные вкладки подключения Moodle Batch закрываются автоматически.

## Проверки

```powershell
npm run test:batch
```

44 проверки покрывают память, запросы Moodle, каскад, ограничение повторов,
остановку, восстановление истории, авторизацию локального сервиса и установленное
MV3 расширение в Chromium. Браузерный тест нажимает кнопку на синтетической
странице Moodle, запускает пакет и переоткрывает панель без повторной отправки.
Живая проверка сервиса 9 октября 2026: тест 374707, попытка 9065004,
10/10 (100%) с первой попытки; 4 ответа из памяти и 1 GPT Web, все подтверждены
Moodle. Установка новой панели в личный Яндекс и запуск из неё остаются отдельной
проверкой; прежние живые результаты движка описаны в BATCH_RUNNER.md.

Рабочее расширение находится в `batch-extension` и использует пакетный движок.


При потере подключения к Playwright сервис проверяет наличие контекста и
переподключается перед отправкой нового запроса. Начатый запрос с неопределённым
исходом при этом не отправляется повторно.

Выбранные тесты собираются перед общим решением. Каждый вопрос получает
идентификатор теста, попытки и номера; перед отправкой Moodle восстанавливается
родной номер вопроса. Материал привязан к конкретному тесту. Общие пакеты
ограничены 40 вопросами и консервативным объёмом входа: 48 000 символов для
Jev и 100 000 для Web. Это ограничители объёма, а не точный подсчёт токенов.
Большие самостоятельные материалы разделяются на пакеты; длинный отдельный
материал сокращается выборкой релевантных фрагментов. Повторные попытки
объединяют только тесты, которые ещё не достигли максимума.

GPT Web начинает с Instant. Только неподтверждённые вопросы повторно проверяются
в Medium, затем High, в той же беседе, максимум два уточнения. Уровень явно
выбирается и проверяется по интерфейсу; недоступность уровня останавливает запрос
с GPT_WEB_REASONING_UNAVAILABLE. Журнал сохраняет уровень и URL беседы.
При потере ответа начатый запрос не пересылается даже после изменения пакета.

Новому ответу нужна точная цитата минимум 20 символов. Цитата из учебного
материала сверяется с материалом именно этого теста. Цитата из интернета
сверяется с публичным текстом страницы по URL, реально полученному в веб-поиске;
загрузка не использует cookies личного браузера. Недоступные страницы, неподтверждённые
цитаты и уверенность ниже 0.85 отправляют вопрос на следующий уровень проверки.
Если HTTP возвращает только оболочку JavaScript, источник читается в отдельном
контексте Chromium без личных cookies. Обычные запросы загрузки разрешены только
к тому же публичному сайту; запросы к другим адресам и WebSocket блокируются.
Табличные разделители и переносы строк нормализуются, но слова, числа и их порядок
остаются частью проверяемой цитаты. Существующие неподтверждённые журналы можно
перепроверить новым чтением источника без повторной отправки модели.

Проверенные ответы незавершённой попытки также переиспользуются при изменении
состава пакета. Для этого сохраняется отпечаток вопроса, формата, контекста и
исключённых вариантов. Изменение этих данных требует нового решения;
неизвестный исход запроса по-прежнему блокирует повторную отправку.
Ответ Jev тоже получает проверку цитаты через Web; если вариант подтверждён,
авторство Jev сохраняется. Уже подтверждённая Moodle память используется сразу.
Совпадение цитаты подтверждает её происхождение, но не гарантирует правильную
трактовку: окончательная проверка правильности остаётся за обратной связью Moodle.
Если после High остались спорные вопросы, этот тест не отправляется;
другие полностью решённые тесты могут отправиться.

Проверка пакета 374776/374777/374781/374784/374790/374793: четыре ответа Jev
были использованы в отправленных попытках, все четыре подтверждены Moodle.
Все шесть тестов достигли 100%. Последний 374793 получил максимум в High.

Скрытие Moodle обратной связи при повторном чтении не удаляет ранее
подтверждённые результаты и исключённые ошибки. Из истории запусков восстановлены
пять наблюдений, которые прежний импорт успел заменить на unconfirmed.

Живая проверка отдельного проекта: 308235 — 100%; 308230 — 7/7 (100%).
После исправления чтения публичного источника последняя попытка 308230 завершена
без новых обращений к Jev или GPT Web: 2 ответа из памяти и 5 из проверенных
журналов. Сессия Moodle сохраняется при успешном подключении и штатном закрытии
сервиса, чтобы обновлённые cookies не терялись при перезапуске.
