# Пакетная версия: Moodle, хранилище и решение

Дата: 9 октября 2026.

Новая версия использует Node.js 24, уже установленный Playwright и встроенный SQLite.
Текущий запуск читает существующие попытки, импортирует обратную связь Moodle и
сопоставляет вопросы с хранилищем. Доступны извлечение материалов и каскад
хранилище → Jev → GPT Web, подготовка итогового запроса и отправка существующей активной
попытки с импортом результата. Новая попытка создаётся только с явным `--start`.

## Запуск

Из папки проекта:

```powershell
npm run batch -- --quiz 374697 --quiz 374703
```

`--quiz` — ID Moodle-модуля из `view.php?id=...`, можно указать несколько.
Программа читает историю завершённых попыток выбранных тестов. Затем собирает активную
попытку, если она существует; иначе показывает вопросы последней завершённой попытки
с явной пометкой. Новую попытку текущая команда не создаёт.

Для конкретной существующей активной попытки:

```powershell
npm run batch -- --quiz MODULE_ID --attempt ATTEMPT_ID
```

Параметры: `--origin`, `--auth`, `--db`, `--report`, `--context`, `--solve`,
`--gpt-auth`, `--gpt-profile`, `--gpt-browser`, `--gpt-extension`, `--gpt-visible`,
`--prepare-submit`, `--submit`, `--start`.
Справка: `npm run batch -- --help`.

По умолчанию авторизация берётся из `.playwright-mcp/reference-auth/cookies.json`.
Поддерживаются массив cookies из экспорта браузера и Playwright storageState.
Значения cookies не выводятся. Сессия проверяется чтением текущего профиля.

Локальные файлы:

- `.playwright-mcp/batch/answers.sqlite` — база наблюдений.
- `.playwright-mcp/batch/report.json` — вопросы, сопоставленные ответы и сводка.

Эта папка исключена из Git. Файлы содержат учебные данные и идентификаторы аккаунта;
пользовательский путь `--db`/`--report` также следует выбирать вне публикуемых файлов.

## Правила хранилища

- Ключ включает origin, аккаунт, курс, тип, полный текст и состав вариантов/строк.
  Перестановка вариантов и строк matching не меняет ключ. Регистр и пунктуация
  сохраняются; удаляются только различия Unicode NFC и пробелов.
- При передаче `contextHash` он входит в ключ: другой материал создаёт другую запись.
  Подтверждённые исторические Moodle ответы связываются
  с точным вопросом и курсом. Автоматическая инвалидизация при обновлении материалов
  пока не реализована.
- Сохраняются выбранный ответ, outcome и точная исходная попытка. Повторный импорт
  того же наблюдения обновляет запись и не увеличивает их количество.
- Неверный/частично верный multiple или matching исключает только полный набор
  или полное соответствие. Отдельные элементы из этого вывода не исключаются.
- Явно показанный правильный choice/text сохраняется отдельно от неправильного
  выбранного ответа. Multiple разбирается только при однозначном сопоставлении текста;
  неоднозначный текст сохраняется как обратная связь. Расшифровка показанных
  соответствий matching пока не реализована, подтверждённое выбранное соответствие поддерживается.
- Несколько разных подтверждённых ответов или один ответ с противоречивыми оценками
  дают `conflict`, без автоматического выбора/исключения.
- Неподтверждённые ответы сохраняются как наблюдения, но не становятся `known`.
- Дублирующиеся тексты вариантов/строк, неподдерживаемые элементы и изображения/
  визуальные формулы дают `unsupported`. Текст не угадывается из изображения.

## Сбор страниц

HTTP GET выполняется Playwright с локальной сессией, внутри заданного origin.
HTML разбирается в одном изолированном Chromium без выполнения скриптов страницы
и с блокировкой загрузки внешних ресурсов. Это разбор полученных страниц, а не
навигация по Moodle через клики.

Переходы между страницами ограничены исходными аккаунтом/курсом/тестом/попыткой.
Полнота проверяется по навигационному списку slots. При пропусках, смене scope,
логине или ошибке сети запуск завершается с кодом причины, без фиктивного результата.
Страницы ограничены 5 МБ после получения, число страниц — 100. Playwright буферизует
ответ до этой проверки; streaming потребуется, если размеры страниц станут проблемой.

## Контекст и модели

```powershell
npm run batch -- --quiz 374697 --quiz 374703 --solve
```

`--context` только извлекает материалы; `--solve` также решает оставшиеся вопросы.
Материалы выбираются перед тестом в той же секции курса, до предыдущего теста:
максимум 6 файлов, каждый до 10 МБ. Поддерживаются HTML, обычный текст, PDF и Word.
PDF читается уже установленным PDF.js из runtime Codex; путь можно задать через
`PDFJS_PATH`. Для DOC/DOCX нужен установленный Microsoft Word на Windows.
Результат извлечения кешируется по хешу содержимого в `.playwright-mcp/batch/materials/`.
Неполный контекст отмечается как `partial`; Jev использует только `ready`.

Jev (`jev-1.13.0`) вызывается через TypeSafe API. Ключ берётся из `TYPESAFE_API_KEY`
или локального Windows-хранилища JevRouter. Choice, multiple и matching проходят
проверку полноты и уверенности; текстовые и нерешённые вопросы переходят в GPT Web.
В GPT включается веб-поиск, проверяются JSON, ID вариантов, исключённые комбинации
и ссылки, действительно присутствующие в ответе. Пакеты содержат до 8 вопросов.
Из длинного контекста выбираются фрагменты по словам вопросов; полнота такого
сокращения не гарантируется, поэтому неподтверждённый ответ остаётся кандидатом.

Ответы моделей имеют статус `candidate` или `needs_review`, а подтверждённые
Moodle ответы — `confirmed`. Кандидат не становится известным правильным ответом
до обратной связи Moodle. Конфликты и неподдерживаемые вопросы не решаются автоматически.
Отчёт сохраняет решения отдельно от состояния хранилища.

Для текстовых ответов перенесены инструкции и `normalizeShortAnswerForQuestion`
из userscript 3.1.7: сохранять словесное число и грамматику источника, возвращать
только пропущенную часть, убирать повтор слов после пропуска, сокращать ответы
на вопросы «ли?» до «да»/«нет» и обрабатывать диапазоны. Например, «трое суток»
для «… суток» превращается в «трое». Исходный ответ сохраняется как `rawAnswer`,
если он изменился. Нормализованный ответ проверяется по исключениям Moodle.
Подтверждённые ответы из хранилища сохраняются без преобразований; numerical
отличается от shortanswer и не проходит эти текстовые правила.
Старая функция не превращает «3» в «трое»: точную форму должен дать провайдер
по источнику, автоматическое угадывание скрытого эталона не добавлено.
Версия web-журнала изменена для новых инструкций; старые pending-запросы
продолжают блокировать повторную отправку.

Журнал `.playwright-mcp/batch/operations/` сохраняет завершённые запросы с привязкой
к попытке, вопросам и контексту. Запись `pending` означает неопределённый результат:
автоматический повтор блокируется с `UNKNOWN_MODEL_OUTCOME`. Перед ручным повтором
нужно проверить, был ли запрос выполнен; удалять журнал без такой проверки нельзя.

## Авторизация GPT Web

По умолчанию используются `.playwright-mcp/reference-auth/cookies_gpt.json`.
Если сайт требует обычной проверки браузера или входа:

```powershell
npm run batch:gpt-login
```

Откроется отдельный профиль. Пройдите проверку/вход и нажмите Enter в терминале,
когда появится поле сообщения. Профиль и состояние сохраняются локально;
исходный файл cookies не перезаписывается. Cookies импортируются только когда
в профиле ещё нет cookies ChatGPT; при неготовом интерфейсе окно остаётся открытым.
После этого:

```powershell
npm run batch -- --quiz 374697 --quiz 374703 --solve --gpt-visible
```

Это однократная подготовка сессии; пакетный запуск сам отправляет вопросы.
Сайт может повторно потребовать проверку. Проверка не обходится, при блокировке
программа завершается с причиной и сохраняет отчёт.

Для установленного браузера на Chromium можно передать login-helper
`--executable-path "C:\path\browser.exe" --profile .playwright-mcp/batch/other-profile`.
Пакетный запуск должен использовать тот же путь через `--gpt-browser` и тот же
профиль через `--gpt-profile`. Совместимость стороннего браузера требует живой
проверки; основной профиль обычного браузера не используется.

### Подключение через Playwright Extension

Расширение позволяет подключиться к обычному открытому браузеру с текущей
авторизацией. Для Яндекса указываются путь браузера и каталог его профилей:

```powershell
npm run batch:gpt-login -- --extension --profile "$env:LOCALAPPDATA\Yandex\YandexBrowser\User Data" --executable-path "C:\Program Files\Yandex\YandexBrowser\Application\browser.exe"
```

В окне расширения разрешите подключение `Moodle Batch` и выберите вкладку
ChatGPT. Helper проверяет доступность поля сообщения; cookies основного
профиля не экспортируются. Если выбранной вкладки нет, helper открывает собственную
вкладку ChatGPT и закрывает её после проверки. Закрытие соединения оставляет обычный браузер открытым.

Пакетный запуск:

```powershell
npm run batch -- --quiz 374697 --quiz 374703 --solve --gpt-extension --gpt-profile "$env:LOCALAPPDATA\Yandex\YandexBrowser\User Data" --gpt-browser "C:\Program Files\Yandex\YandexBrowser\Application\browser.exe"
```

Соединение создаётся только при необходимости GPT Web и используется для всех
пакетов текущего запуска. Каждый пакет получает отдельную новую вкладку; программа
закрывает созданные ею вкладки и служебные страницы подключения клиента `Moodle Batch`.
Служебные страницы закрываются после открытия рабочей вкладки и при завершении
обращения; другие клиенты расширения и личные вкладки сохраняются. Программа отсоединяется в конце. Для автоматического
подключения расширение поддерживает `PLAYWRIGHT_MCP_EXTENSION_TOKEN`; без него
первое подключение требует разрешения пользователя.

Используется relay уже установленного Playwright без новых зависимостей.
Его внутренний `createBrowserWithInfo` требует повторной проверки при обновлении
Playwright. Живая проверка: через расширение в Яндексе отправлен один синтетический
запрос с веб-поиском, получен JSON и две ссылки, подтверждённые результатами инструмента
`web.run`. Ответ восстановлен без повторной отправки. Поле распознаётся по `role="textbox"`
и `contenteditable`, а также по прежнему `#prompt-textarea`.

Токен можно сохранить в `.playwright-mcp/reference-auth/playwright-extension-token.txt`.
Этот файл исключён из Git и читается только при подключении; значение не выводится.
Переменная окружения `PLAYWRIGHT_MCP_EXTENSION_TOKEN` имеет приоритет.

В новом интерфейсе ChatGPT текст ответа недоступен через DOM. После завершения
программа читает только текущий разговор запросом GET в авторизованной вкладке.
Токен остаётся внутри браузера. Проверяются единственный пользовательский запрос,
его requestId и единственный финальный ответ; промежуточные рассуждения не извлекаются.
Ссылки проверяются по результатам `web.run`, а не только по заявлению модели.

## Итоговый запрос Moodle

`--prepare-submit` включает решение и проверяет возможность отправки без POST.
`--submit` включает решение и завершает **существующую активную** попытку:

```powershell
npm run batch -- --quiz MODULE_ID --attempt ATTEMPT_ID --prepare-submit --gpt-extension --gpt-profile "$env:LOCALAPPDATA\Yandex\YandexBrowser\User Data" --gpt-browser "C:\Program Files\Yandex\YandexBrowser\Application\browser.exe"
```

Для отправки замените `--prepare-submit` на `--submit`. Без этих параметров
запуск только читает и решает. Завершённый обзор отправить нельзя.

Для полного цикла добавьте `--start --submit` к обычному запуску выбранных тестов.
`--start` использует существующую активную попытку; если её нет, отправляет
нативную форму `startattempt.php`. Создание также защищено журналом от повторного
POST. Неопределённый исход отмечается `UNKNOWN_START_OUTCOME`; повторное чтение
view позволяет найти созданную активную попытку. Пароль, обязательная форма
preflight или защищённый браузер останавливают запуск с `MOODLE_PREFLIGHT_REQUIRED`.
Программа не принимает эти подтверждения автоматически. Нельзя сочетать `--start`
с явно заданным `--attempt`.

Перед POST повторно читаются все страницы активной попытки. Изменение вопроса
или sequencecheck останавливает отправку. Поддерживается `deferredfeedback` для
choice, multiple, matching и text. Все вопросы должны быть решены; конфликты,
неподдерживаемые вопросы, `needs_review` и исключённые ответы блокируют запрос.
ID ответов преобразуются в реальные имена/значения полей свежей страницы.

Один multipart POST отправляется в `processattempt.php` с полным списком `slots`,
sequencecheck каждого вопроса, sesskey и `finishattempt=1`. Это соответствует
[обработчику Moodle](https://github.com/moodle/moodle/blob/MOODLE_39_STABLE/mod/quiz/processattempt.php)
и [полям формы Moodle](https://github.com/moodle/moodle/blob/MOODLE_39_STABLE/mod/quiz/renderer.php).
Совместимость с активной попыткой данного сайта пока проверена только синтетически.

Журнал операции привязан к аккаунту, тесту и попытке, создаётся до POST.
Автоматические повторы POST отключены. Неопределённый исход оставляет `pending`
и блокирует повтор с `UNKNOWN_SUBMISSION_OUTCOME`; нужно прочитать историю Moodle.
После подтверждённого перенаправления на review программа собирает результат
и импортирует обратную связь в SQLite. Отсутствующая оценка остаётся `unconfirmed`.
Кандидаты моделей не объявляются правильными без обратной связи.

## Проверки

```powershell
npm run test:batch
```

Проверяются сохранение после переоткрытия базы, перестановка вариантов, повторный
импорт, изоляция scope/контекста, полные ошибочные комбинации, конфликты,
показанный правильный ответ, matching/text, cookies, разбор без скриптов и
полнота нескольких страниц. Fixtures синтетические; cookies и живые вопросы в тесты не включены.

Живая проверка 9 октября 2026: два выбранных теста, три завершённые попытки,
15 наблюдений: 13 `correct`, 2 `incorrect`. На последних попытках каждого теста
найдены все 5 подтверждённых ответов. Повторный запуск проверяет отсутствие
дублирования. Проверка активной попытки и новых типов DOM остаётся отдельным этапом.

Текущий этап: 23 теста прошли, включая каскад, исключения, журнал и синтетический
GPT DOM с единственной отправкой и цитатами. Реально извлечены два PDF
(65 881 и 27 994 символов) и DOC (19 666 символов). Прямой запрос Jev проверен
на синтетическом вопросе. GPT Web с веб-поиском реально проверен через Playwright
Extension; отдельные профили ранее останавливались на «Just a moment…».
Повторный запуск двух тестов 9 октября взял 10/10 ответов из хранилища без вызова
моделей. Helper успешно подключился к Яндексу с автоматическим закрытием служебных
вкладок. Создание и завершение попытки реализованы и проверены синтетически;
живые POST Moodle проверены повторным прохождением теста 6 (модуль 374707).

Повторная попытка 9064965: оценка выросла с 6/10 до 8/10; Moodle подтвердил
4 правильных ответа из 5. Создание попытки, один итоговый POST, чтение review и
импорт всех 5 наблюдений прошли на реальном сайте. Новая попытка получила другой
набор вопросов. Четыре уже полученных решения были использованы повторно;
ошибочный вариант сохранён для следующих попыток.

В банке обнаружены повторяющиеся тексты вариантов choice. Такие вопросы допускаются,
если выбранный текст соответствует ровно одному реальному варианту. Выбор повторяющегося
текста блокируется: нельзя восстановить точный Moodle вариант по текстовому ID.
Для multiple повторяющиеся варианты остаются неподдерживаемыми.


## Анализ всех курсов на странице оценок

Запуск из каталога проекта:

```powershell
npm run batch:overview -- --serve
```

Установите в Tampermonkey [скрипт страницы оценок](http://127.0.0.1:49804/grades.user.js),
затем откройте [оценки Moodle](https://sdo.sibupk.su/grade/report/overview/index.php).
Сервис должен оставаться запущенным. Без `--serve` выполняется один анализ с сохранением
отчёта. Параметры: `--concurrency 6` (1–12), `--port 49804`, `--auth`, `--origin`,
`--db`, `--report`. Другой порт автоматически подставляется в выдаваемый скрипт.

Сохранённая сводка появляется сразу при открытии страницы из локального кеша
Tampermonkey, привязанного к сайту и аккаунту. Сервис также поднимает последний
завершённый отчёт из `.playwright-mcp/batch/overview.json`. Свежие оценки появляются
по мере получения; подробная проверка попыток продолжается в фоне. Кнопка
«Обновить анализ» запускает обновление, повторные нажатия не дублируют текущий запуск.
Сервис обновляет сводку старше 60 секунд при обращении страницы.

Обход получает все курсы со страницы оценок, оценки тестов и полный список тестов
с темами со страниц курсов. По умолчанию одновременно выполняется не более шести
задач во всём обходе. HTML разбирается через отдельные DOMParser документы без
загрузки страниц, исполнения скриптов и загрузки ресурсов.

Для каждого теста показаны оценка, активная попытка, подтверждённые ответы и
исключения последней доступной попытки. Все доступные обзоры импортируются в
существующее хранилище ответов. Количество известных ответов относится к вопросам
доступной попытки: оно не означает, что известен весь скрытый банк Moodle.
Нет оценки, нет попытки и ошибка чтения отображаются разными состояниями.
Обход только читает Moodle: он не начинает и не завершает попытки и не вызывает модели.

Локальный сервис слушает только 127.0.0.1, проверяет сайт и аккаунт. Отчёт и cookies
исключены из Git; скрипт получает сводку, не cookies и не содержимое вопросов.

не обнаружено. Первый полный обход занял 163,4 секунды; повтор после перехода на DOMParser —

использует сохранённые данные; свежий полный обход требует сетевых запросов.
